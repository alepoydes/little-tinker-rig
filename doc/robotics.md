# Робот и органы управления

## Подключить хаб

Нужен хаб с установленной прошивкой Pybricks. Установку прошивки и совместимость
моделей описывает [официальное руководство](https://pybricks.com/learn/getting-started/pybricks-environment/).

```sh
uv run --extra qt --extra pybricks pyblocks-qt examples/motor.py
```

**F7 / Connect** запрашивает Bluetooth-имя хаба. Пустое имя выбирает первый
найденный подходящий хаб. **F5 / Run** сохраняет и передаёт программу;
**F6 / Stop** останавливает её. Вывод `print` появляется в Console.
В TUI используются те же клавиши.

Запуск из терминала с ожиданием завершения:

```sh
uv run --extra pybricks pyblocks run examples/motor.py --name 'My hub'
uv run --extra pybricks pyblocks run examples/motor.py --transport usb
```

Bluetooth и USB реализованы через публичные API `pybricksdev`. Доступность USB
зависит от хаба, прошивки и прав ОС. Графический диалог подключает по Bluetooth;
для USB используйте CLI или API `Connection.connect(transport="usb")`.

## Первое движение

Пример `examples/motor.py` ожидает мотор в порту A, поворачивает его на 90 градусов
со скоростью 300 градусов/с и тормозит. Проверьте порт перед запуском. Для первой
проверки расположите модель так, чтобы она могла свободно выполнить движение.

Библиотека содержит создание мотора и датчика цвета, вращение и остановку,
ожидание, проверку отражения и следование вдоль линии. Объекты `Motor`,
`ColorSensor` и `DriveBase` выполняются на хабе; редактор не исполняет эти шаблоны.

## Экранный джойстик

Передача управления использует нормализованные оси от −1 до 1, 16 кнопок
в виде битовой маски и ползунок от 0 до 1. Вверх — положительное `left_y`.
Экранный джойстик и физический геймпад передают одинаковый формат.

Создайте обычный вспомогательный Python-файл рядом с программой:

```sh
uv run pyblocks controller examples/pyblocks_controller.py --write
uv run --extra qt --extra pybricks pyblocks-qt examples/drive_controller.py
```

В примере два мотора подключены к A и B. Размер колеса и расстояние между
колёсами нужно заменить на размеры своей модели, в миллиметрах.

После запуска программы откройте Robot → Controls и включите **Send controls**.
Перетаскивайте джойстик; отпускание возвращает его в центр. Стрелки клавиатуры
работают, пока джойстик в фокусе. Кнопки 1–4 соответствуют битам 0–3 поля
`buttons`; ползунок доступен как `slider`.

На хабе:

```python
from pyblocks_controller import Controller
from pybricks.tools import wait

controller = Controller()
while True:
    controller.update()
    drive.drive(controller.left_y * 300, controller.left_x * 120)
    wait(20)
```

Вызывайте `update()` в каждом проходе цикла. Если свежие сообщения не приходят
500 мс, значения становятся нулевыми. Программа должна применять эти значения
к моторам; сам объект Controller не управляет мотором и не заменяет Stop.

Используется поток stdin и публичный `read_input_byte`, доступный в Pybricks 3.3+.
Это позволяет работать с текущим host API без собственной реализации BLE/USB.
Программа с Controller не должна одновременно читать stdin другим способом.
Состояние передаётся с частотой до 20 Гц; очередь устаревших кадров не накапливается.

## Физический геймпад

Добавьте `--extra gamepad` при запуске и включите **Physical gamepad** в Controls.
Используется SDL через pygame-ce. Первые четыре оси назначаются левому и правому
стикам; конкретное назначение зависит от устройства. Небольшая мёртвая зона
убирает дрожание около центра. Проверяйте направления до движения модели.

## Проверка без оборудования

Автотесты проверяют кодирование, частичные кадры и сброс устаревшего управления.
Реальная радиосвязь, драйвер USB и поведение конкретного робота требуют проверки
на соответствующем оборудовании.
