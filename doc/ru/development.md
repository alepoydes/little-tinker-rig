# Разработка

GitHub Actions использует предоставленный GitHub Ubuntu-воркер с Qt в режиме
offscreen. Проверяются код, документация, переводы, тесты и сборка дистрибутивов.
Проверки оборудования и нативного OpenGL остаются локальными; собственный воркер
для обычного CI не нужен.

Перед включением стороннего кода или модели проверяйте лицензию конкретного
источника и сохраняйте авторство. Лицензия репозитория не распространяется
автоматически на загрузки с сайта автора. Материалы без разрешения на
распространение оставляйте внешними ссылками: их содержимое не должно попадать
в исходники, дистрибутивы и публикуемую историю Git. Инструменты загрузки и
адаптации должны соблюдать ту же границу.

Среда разработки uv закреплена на Python 3.13 для использования готовых бинарных
пакетов зафиксированных зависимостей рендера. Минимальная версия Python для
приложения остаётся 3.11.

Геометрия окна сохраняется и восстанавливается штатным API Qt вместе с
развёрнутым/полноэкранным состоянием и коррекцией положения при смене мониторов.
Запись выполняется после подтверждения закрытия и успешной очистки восстановления.
Закрытое свёрнутым окно при следующем запуске должно стать видимым.

Старые Python-файлы читаются в объявленной кодировке; Save и Save As всегда пишут
UTF-8 без BOM. Действующее объявление кодировки нормализуется общей функцией
модуля сохранения. Интерфейс проводит изменение текста через историю отмены
перед обновлением сохранённого состояния. Проверяйте байты, повторное открытие,
текст редактора, Undo и повторное сохранение, включая ошибочные черновики и BOM.
Выделение привязывается к текущему синтаксическому дереву после изменения документа
при сохранении или восстановлении, как и после интерактивных правок.

Open читает файл назначения после решения Save/Discard/Cancel. Повторное открытие
текущего файла использует только что сохранённые байты и новый хеш для проверки
внешних изменений; ошибка чтения оставляет текущий документ открытым.

Область подтверждения закрытия совпадает с областью сохранения. Архив урока владеет
всеми программами: при закрытии окна решение принимается один раз для проекта,
с учётом черновиков во всех вкладках. Сохранение другой вкладки того же архива
не должно отменять Discard; Cancel сохраняет рабочую копию и открытые документы.

Модули прошивки зарегистрированы по полному имени и не обязаны быть атрибутами
родительского модуля. При поиске доступных классов загружайте модуль напрямую;
нельзя полагаться на семантику CPython для `import pybricks.hubs as hubs`.
Проверки монитора должны воспроизводить эту границу импортов наряду с телеметрией
портов и остановкой моторов. Одна компиляция не обнаруживает отсутствие атрибутов.
Асинхронные UI-тесты ждут завершения всего наблюдаемого перехода, включая состояние
подключения и доступность операций: отдельные сигналы очереди могут обрабатываться
в разных итерациях цикла событий.
Неизвестные устройства не читают телеметрию, по которой можно обнаружить отключение.
Периодически проверяйте их заново и удаляйте отключённые записи, сохраняя объекты
работающих поддерживаемых устройств. Проверяйте замену как сразу, так и после
промежуточного пустого порта.

У каждого inline-блока свой выбор Auto/Source/Definition. Авто учитывает принадлежащие
блоку комментарии, но не пустые строки. Текст определения — отображение с
привязкой к исходнику: переключение не меняет документ, выполнение или Undo.
Координаты параметров, наведения, сворачивания и перетаскивания переводятся
обратно в координаты исходного Python. Цельный блок подсвечивается целиком,
включая заголовок и отображаемые комментарии; после раскрытия подсвечиваются его
самостоятельные части. Проверяйте реальные события мыши и цвет результата
для блоков из нескольких команд. Заголовок предшествует всем комментариям блока.

Блок-функция показывает настоящий вызов Python. Подмена имени только на экране
и добавление тела функции возле вызовов недопустимы. Имя совпадает в библиотеке,
вызовах, управляемом определении и предпросмотре. После импортов хранится одно
определение на имя; общие зависимости и обращения из Scratch учитываются при
удалении. Конфликт реализаций или глобальных имён вызывает явную ошибку.
Совпадение имени пользовательской функции не должно давать ей описание блока.
Проверяйте несколько вызовов, комментарии программы, редактирование аргументов,
переход к определению, удаление последнего использования и атомарность ошибок.

Историческое распознавание сравнивает сохранённые определения и их импорты.
Перезагрузка библиотеки их не переписывает. Явное обновление функции заменяет
общее определение для всех вызовов с предварительным diff и единой отменой.
Изменение сигнатуры вызова требует ручного редактирования.

Храните текст определения вместе с AST: дерево задаёт семантику подстановки,
текстовые изменения сохраняют комментарии и оформление. Вспомогательные функции
вычисляют аргументы один раз и изолируют локальные переменные. Их определения
сохраняют пояснения; вставка inline-блока не копирует комментарии в программу.
Проверки охватывают принадлежность комментариев, докстринги, конец области,
смену режима, редактирование параметров, Undo и команды виртуальному роботу
после перевода готовых действий на функции.
При удалении значений параметров по умолчанию используйте границы токенов:
AST не включает лишние обрамляющие скобки в диапазон выражения. Для тел определений
и функций используйте общий алгоритм отступов, учитывающий строки; обычный dedent
меняет содержимое многострочных литералов. Проверяйте выполнением полученных
функций значения в скобках, докстринги и f-строки.

Анализ областей видимости и переименование учитывают все формы объявления имён,
включая захваты match, звёздочные шаблоны и остаток словаря. Тело comprehension
пропускает пространство имён класса; только внешний итерируемый объект вычисляется
в области класса. Проверяйте разрешение имён и результаты выполнения после
посторонних правок, очистки зависимостей и переименования.

Проект использует uv, Python 3.11+ и обычную структуру Python-пакета.
Рабочая версия интерпретатора указана в `.python-version`; точные зависимости —
в `uv.lock`. В окружении разработки устанавливаются все интерфейсы:

```sh
uv sync --all-extras --locked
uv run --all-extras --locked pytest
uv run --all-extras --locked ruff check little_tinker_rig tests tools build_support.py
uv run --all-extras --locked black --check little_tinker_rig tests tools build_support.py
uv build
```

`uv run` синхронизирует окружение с выбранными extras. Для запуска интерфейса
указывайте его явно: `uv run --extra qt little-tinker-rig-qt`.

Линтер и форматирование проверяют приложение, тесты и инструменты. Примеры
сохраняют соглашения исходных авторов и проверяются тестами примеров. Pytest
добавляет корень репозитория в путь импорта: запуск командой и через модуль
должен одинаково находить инструменты разработки.

Ядро использует стандартную библиотеку, platformdirs для каталогов пользователя и Ruff. Ruff запускается через
публичный CLI; конфигурация берётся из пакета, а не из текущего каталога.
Форматирование выполняется только на границе зафиксированной операции.

## Инварианты

- Текст программы — единственное сохраняемое представление программы.
- AST, диапазоны, области отображения и распознавание можно построить заново.
- Зафиксированный основной документ проходит `ast.parse` и `compile` без исполнения.
  Структурная проекция Scratch требует только разбора: `break` вне цикла допустим
  как отложенный фрагмент. Неразбираемый текст хранится в текстовой ячейке.
- Синтаксическая ошибка, ошибка форматирования или переноса не меняет документ
  и историю. Основной текст и Scratch входят в одну транзакцию.
- Диапазоны ядра используют индексы Unicode-символов, полуинтервал `[start, end)`.
  UTF-8-координаты AST преобразуются на входе. Строки нумеруются с 1, столбцы с 0.
- Узлы AST и позиции вставки принадлежат одной ревизии исходника.
- Удаление и перенос выражения с отдельной строки удаляют инструкцию целиком.
  Только вложенное выражение оставляет `...`; пустое тело сохраняет `pass`.
  Скобки при подстановке добавляются лишь для сохранения AST.
- Редактирование выражений сначала заменяет поддеревья. Текстовая проекция
  проверяется по этому независимому дереву, а не по другой текстовой подстановке.
  Связанный параметр редактируется так же до распространения на все вхождения.
  Проверяйте приоритет, ассоциативность, комментарии и единый Undo при переносе
  и копировании.
- Подсказки Python используют публичный Jedi Script API и официальный пакет
  `pybricks` из Qt extra. Одна фоновая очередь последовательно обслуживает общий
  кеш Jedi и хранит только последний ожидающий запрос каждого редактора.
  Между потоками передаются готовые данные подсказок. Изменения текста, курсора,
  пути, потеря фокуса и Escape делают старые результаты неприменимыми.
  Проверяются незавершённые вызовы, Unicode, Undo и анализ импортов без исполнения.
- Тесты проверяют результат и инварианты, а не внутреннее устройство функций.
- Преобразование исходника проверяется отдельно на сохранение комментариев,
  строковых значений (включая многострочные f-строки) и лексических привязок.
  Синтаксическая валидность сама по себе не доказывает сохранность этих данных.
- Сохранение нескольких файлов проверяется с отказом между отдельными записями,
  причём для переноса фрагмента в обоих направлениях.
- Внешние изменения проверяются для исходника и Scratch; контрольная сумма
  соответствует прочитанным или записанным байтам, а не последующему чтению файла.
- Обновление отображения не должно менять логическое выделение. События
  программного обновления виджетов отделяются от пользовательского выбора.
- Исторический шаблон проверяется вместе с реальной встроенной библиотекой:
  общие шаблоны одиночных инструкций не должны скрывать узнаваемый алгоритм.
- Сохранение текста независимо от структурной валидности: недописанный Python
  сохраняется как видимый текст, запуск и переход к блокам требуют проверки.
  Форматирование остаётся отменяемой текстовой операцией.
- Восстановление сохраняет исходные хеши файлов и состояние последнего сохранения;
  внешние правки не становятся молча новой базой. После восстановления AST выделение
  перепривязывается до обновления виджетов. Проверяются блокировки работающих окон,
  Scratch, прерванный перенос снимка и конфликтующие восстановленные версии.
- Ошибки выполнения относятся к снимку отправленного кода и локальных модулей.
  Старые номера строк не подсвечивают изменённый файл. Разбор traceback учитывает
  фрагментацию вывода, не меняет сам вывод и не считает прерывание остановки ошибкой.
- Меню примеров строится из поставляемого каталога без отдельного списка.
  Повторные обновления освобождают старые подменю Qt.
- Поддержка устройства проверяется по доступным API каждой модели. Компиляция
  общего helper не доказывает наличия модулей на BOOST, Inventor или Technic.
- Проверки контроллера наблюдают движение, остановку и показания устройств,
  включая истечение команды и отключение. Отмена загрузки завершается перед
  следующей операцией жизненного цикла, чтобы не оставить процесс или соединение.
- Потоки Qt/asyncio проверяются вместе: имитация одного транспорта не проверяет
  доставку сигналов и своевременную остановку. Для таких тестов среда должна
  разрешать локальный `socketpair`, используемый самим asyncio.

## Проверки без оборудования

`test_virtual.py` проверяет модели Inventor/Prime, BOOST и Technic, выполнение
обычной программы, датчики, тайм-аут моторов, остановку бесконечного цикла и
настоящий код `hub_monitor.py` поверх моделируемого API устройств.
`test_frontends.py` проверяет эти подключения через Qt, движения стиков,
назначения вращения/серво, отключение и зеркалирование физического контроллера.
Qt работает с `QT_QPA_PLATFORM=offscreen`; оборудование и радиосвязь не нужны.

Компиляция служебных программ для MicroPython (extra `pybricks`):

```sh
uv run --extra pybricks python -m mpy_cross_v6 little_tinker_rig/pybricks/hub_monitor.py -o /tmp/little-tinker-rig-monitor.mpy
uv run --extra pybricks python -m mpy_cross_v6 little_tinker_rig/pybricks/hub_controller.py -o /tmp/little-tinker-rig-controller.mpy
```

Wheel проверяется из каталога вне репозитория: справка и настройки форматтера
должны браться из установленного пакета. При изменении документации сборка
включает актуальный `doc/` без второй поддерживаемой копии.

## Стоимость операций

Индекс строится линейным обходом AST. Форматирование и повторный разбор выполняются
при фиксации; наведение и навигация используют готовый индекс. История хранит
снимки текста и Scratch, что подходит для учебных программ небольшого размера.

Перечисление мест переноса проверяет компиляцией один кандидат на список
инструкций: внутри списка контекст компилятора одинаков. Если в документе есть
зависящие от порядка объявления `global`, `nonlocal` или `__future__`, проверяется
каждая позиция. Перед фиксацией готовая программа всегда компилируется заново.
Стоимость обычного случая — O(число списков × размер программы + число позиций).
Для зависимых от порядка объявлений сохраняется точный, но более дорогой путь
O(число позиций × размер программы). Оптимизированный набор целей сравнивается
в тестах с независимым перебором и компиляцией каждого преобразования.

Отказ одного устройства при групповой команде проверяется после успешного
запуска предыдущего мотора: обработчик ошибки должен тормозить и уже начавшие
движение устройства, а не только моторы из предыдущего кадра управления.

## Документы и прямое редактирование

Вкладки документов сохраняют независимые черновики и историю. Команды окна
действуют на активный файл. Перевод не меняет пользовательский текст.
Предварительный вид вставки использует ту же подстановку параметров и защиту
имён, что фиксация. Цели учитывают положение `global`, `nonlocal` и `__future__`.
Редактирование параметра сохраняет приоритет операций и меняет все вхождения
одного параметра шаблона. Поле старой ревизии не может изменить новый документ.

Перенос сначала выбирает геометрическую цель и только затем проверяет её.
Результат проверки кешируется до смены ревизии. Недопустимая позиция не должна
подменяться другой, более далёкой допустимой целью.
Поля параметров и их геометрия пересчитываются при смене ревизии или раскрытии
сниппета; наведение не запускает форматирование.

`test_ux.py` проверяет несколько файлов, сохранность ошибочных черновиков,
совпадение предварительного и вставленного кода, раскрывающиеся поля, пульсацию
фона и перевод интерфейса и справки. `examples/courier.py` проверяется как настоящая
программа виртуального хаба: калибровка, препятствие, доставка, завершение маршрута,
аварийная остановка, истечение времени и отключение датчика. После выхода все
доступные моторы должны тормозиться.

```sh
uv run --extra pybricks python -m mpy_cross_v6 examples/courier.py -o /tmp/little-tinker-rig-courier.mpy
```

## Переводы

Исходный язык подписей Qt и язык по умолчанию — английский. Русский хранится
как перевод. gettext-каталоги находятся в
`little_tinker_rig/locale/<код>/LC_MESSAGES/little_tinker_rig.po`, скомпилированные `.mo` входят
в пакет. `locale/languages.json` задаёт коды языков и их собственные названия
для меню. Babel нужен только разработчику; приложение использует стандартный gettext.

```sh
uv run python tools/translations.py update
# Заполнить новые msgstr в .po и проверить перевод.
uv run python tools/translations.py compile
uv run python tools/translations.py check
```

`update` извлекает явные вызовы `N_` / `tr` и английские docstring сниппетов,
добавляет ссылки на исходники и сохраняет уже готовые переводы. `check` находит
пропуски, неподтверждённые переводы, несовпадающие поля форматирования и устаревший
бинарный каталог. `.po` и `.mo` сохраняются вместе в репозитории.

Статические подписи отмечаются `N_("Caption")`; `qt.localization.localize`
сохраняет английские оригиналы и обновляет подписи без пересоздания виджетов. Динамический
текст создаётся через `tr("Message {name}", name=value)`; подстановка выполняется
после поиска перевода. Пользовательский текст, значения параметров и консольный
вывод не являются сообщениями интерфейса. При добавлении языка создайте раздел
`doc/<код>/`, сохранив относительные пути страниц: так текущая страница справки
сохраняется при переключении языка. Изображения с текстом находятся в `doc/<код>/images/`, общие иллюстрации
без текста могут храниться в `doc/images/`. Для английского каталог не нужен.


## Проверка ленты Scratch и отображения

Перенос хранит ревизию владельца и фиксирует источник и назначение одной
операцией. Отмена или неверный контекст не удаляет исходный фрагмент. Изменение
только Scratch не пересоздаёт синтаксис основного документа. После undo нельзя
публиковать устаревшую проекцию ячейки обратно в восстановленное состояние.

Описания и единицы — слой отображения. Проверки сравнивают исходник до и после
отрисовки, позиции видимого текста после вставки и пиксели полос вложенности на
пустых строках. Первый блок также должен иметь место для описания. Проверка
переноса включает единственный блок документа: отсутствие внутренних целей
переноса не должно запрещать отцепление в Scratch.

Библиотечные примеры собираются через Session, затем исполняются на виртуальных
Inventor, BOOST и Technic. Это обнаруживает отсутствующие зависимости и неверные
единицы, которые невозможно проверить одним разбором AST. Цвет и распознавание
проверяются для полного определения устройства и для одноимённых методов
разных типов. `test_scratch.py` проходит события drag/drop Qt и общую отмену.

Импорты в статических шаблонах объявляют зависимости, в том числе для выражений
по умолчанию. Для этих файлов правило F401 отключено: автоматическое удаление
«неиспользуемого» импорта может сломать развёрнутую программу. Регрессионные
проверки выполняются после линтера и форматирования.

Отступ цели переноса определяется горизонтальной позицией указателя, включая
пустую строку после последнего блока. Позиция текстового курсора там всегда
равна нулевому столбцу и не подходит для выбора вложенности.


## Документация и группы блоков

`doc/en/` и `doc/ru/` содержат одинаковые пути Markdown-страниц. Английский —
основная версия; при изменении поведения обновляются оба руководства. Язык
справки следует интерфейсу с сохранением страницы или раздела блока. При
отсутствии перевода приложение показывает английскую страницу; проверка
`tools/check_docs.py` запрещает пропущенные страницы в поставке и проверяет
локальные ссылки и якоря. README, комментарии, docstring, проектные заметки
и описания коммитов пишутся на английском. Сохранённый выбор языка имеет
приоритет; при первом запуске или неверной настройке выбирается английский.

`snippet_groups()` строит группы по идентификаторам коллекции и модуля,
исключая исторические шаблоны. Библиотека и справка используют одни группы.
Для каждой группы создаётся одна страница с описаниями, параметрами, кодом
и устойчивыми якорями по именам функций. F1 находит группу и раздел блока.
Отдельной поддерживаемой копии описаний в Markdown нет. Поиск учитывает всю
страницу группы, а «Назад» — переходы между её разделами.

## Примеры наборов LEGO

Сборка программы с пустого документа — разовая ручная проверка организации
редактора: достаточно ли инструментов и легко ли их найти. Выводы сохраняются
в `AI`. Полные сценарии сборки через GUI не входят в регулярный прогон тестов;
короткие регрессионные тесты защищают семантику и поведение интерфейса, которые
могут случайно сломаться.

Программы в `examples/pybricks` должны собираться из стандартной палитры.
Универсальное присваивание или вызов функции не считается покрытием неизвестного
API устройства. Проверяем реальные вызовы, повторно собираем распознанные
фрагменты из шаблонов и сравниваем порядок команд и итоговое состояние виртуального
хаба. При переносе сравниваем и с закреплённой версией исходной программы.
Сохраняем порядок вычисления аргументов, ожидание, режимы остановки, повторные
чтения датчиков и завершение циклов. При замене устаревшего имени API данные
остаются прежними. Упоры и кнопки пульта задаются явно в тестах; неподдерживаемая
физика не должна молча становиться успешной в интерактивном симуляторе.
Имена аргументов симулятора совпадают с Pybricks, включая `run_time(time=...)`.

## Задержка интерактивных операций

При привязке пояснений ищите команды по индексу диапазонов, а не обходите весь
документ для каждого блока. Комментарии определения используют владельцев из
шаблона без повторной подстановки всех вызовов. Совместимость блоков-подсказок
кэшируется для каталога и типа поля; имена устройств зависят от текущей области
видимости.

Измерение включает анализ, компоновку Qt и перерисовку:

```sh
uv run --extra qt python tools/benchmark_editor.py --lines 1000 5000
```

Редактор форматирует программы публичным CLI Ruff с `core/formatting.toml`;
стиль исходников самого проекта проверяет Black из группы зависимостей разработки.
Проекции Scratch разбирают существующий текст без повторного форматирования;
зафиксированные правки по-прежнему форматируются и проверяются. Пока ревизия
не меняется, индексы и данные отображения переиспользуются. Поиск узлов и отбор
непересекающихся сниппетов используют индексы; рисуются видимые строки. Изменения
компоновки Qt выполняются пакетом. Переносы из библиотеки и из программы
замеряются отдельно, с проверкой отмены.

Регрессии проверяют щелчки по каждому значению enum, обычные поля имён,
сохранность исходника при открытии списка, цвета комментариев и линию вставки
перед всеми описаниями. Кнопки окна проверяются щелчками: одних флагов
окна недостаточно для проверки оформления рабочего стола.

## Проверки переноса и прошивки

Перенос — временная проекция неизменённого документа. Во время движения нельзя
создавать вторую редактируемую копию исходника или записи Undo. Перед фиксацией
восстанавливаются временные форматы Qt. Проверяются Esc с продолжением движения
при нажатой кнопке, возврат на прежнее место, неверный контекст, выражения и Scratch.

При добавлении строки вставки проверяется глобальная координата той же строки
исходника и положение мыши относительно неё: короткий документ, края прокрутки,
заголовки составных блоков и ячейки Scratch. Сначала завершается компоновка ячейки
и резервируется временное место прокрутки, затем компенсируется положение.
Снимок экрана сам по себе этот инвариант не проверяет. Фон описания обязан
сохранять полосы родительских блоков.

Проверяется загрузка без исполнения и запуск сохранённого снимка после изменения
или удаления исходника и локальных импортов. Подготовка прошивки не обращается
к оборудованию. Метаданные проверяются до подключения, физическая модель — до
стирания, проверенная SHA-256 — повторно в процессе записи. Автотесты подменяют
границы транспортов; проверка физической прошивки учитывается отдельно. Отдельный
процесс изолирует публичные функции DFU, способные вызвать SystemExit.

Состояние подключения отделено от телеметрии. Отключение отменяет незавершённое
подключение; занятость снимается после очистки, а запоздалые уведомления отменённой
попытки не восстанавливают соединение. Нативные USB-драйверы работают в дочернем
процессе: блокирующий вызов не должен мешать отмене. Если штатное закрытие зависло,
завершите процесс и дождитесь его выхода. Проверяйте тайм-аут, отмену, повторное
подключение и зависшее закрытие на искусственном процессе без поиска реальных хабов.

При сетевой ошибке и ограничении запросов сохраняйте версии и контрольные суммы
каталога. Сохраняйте срок повторного запроса к GitHub API; REST и лента выпусков
используют одинаковые адреса архивов. Обновление каталога не скачивает прошивки,
повторная подготовка использует проверенный архив из кеша. Проверяйте это локальными
пакетами и искусственными HTTP-ошибками, без повторных запросов к настоящему API.

Возможности Pybricks используйте через публичные API; идентификаторы USB берите
из pybricksdev. Последовательный адаптер временно восполняет отсутствие транспорта
в библиотеке. Не копируйте правила udev Pybricks. Ошибки открытия порта поясняйте
до передачи через границу процесса, сохраняя причину по errno и исходную ошибку.
Советы о группах Linux опираются на метаданные устройства, членство учётной записи
и группы процесса; нельзя предлагать включение в административную группу.
Проверяйте отсутствие членства, старый сеанс, ошибки ACL, занятый и исчезнувший порт.
Справка интерфейса работает офлайн. Проверка Inventor не подтверждает работу на EV3.

USB Serial использует SPIKE COBS, а не обычный COBS с нулевым разделителем.
Разбиение потока на части, объединение сообщений и повреждённые кадры не должны
менять границы транзакций. Запросы выполняются последовательно; ответы сопоставляются
по тегу или селектору чтения. После тайм-аута либо отмены соединение закрывается,
чтобы запоздалый ответ не подтвердил другую команду. Перед загрузкой метаданные
сохранённой программы обнуляются; размер записывается только после успешной
передачи всех частей. Запуск ждёт состояния покоя после подтверждения команды
старта, а не старого статуса. BLE и прежний USB остаются на публичных адаптерах.

Метаданные v3 разделяют тип хаба и аппаратный вариант. Подготовка проверяет все
образы; зафиксированный публичный установщик Pybricks определяет MCU до стирания.
Нельзя передавать новый F4/H5-образ старому DFU-коду с фиксированным адресом.
`pybricks/installer.json` фиксирует ревизию и хеши инструментов, лицензии и
загрузчика: они хранятся в пользовательском кеше и проверяются перед запуском.
Обновляйте их вместе после проверки. Аппаратные цели не определяют виртуальные
профили: поддержка USB для EV3 не означает наличие его симулятора, BLE или монитора.

## Структурные поля и общая отрисовка

Имена, части выражений, операторы и списки привязаны к одной ревизии Syntax.
Индекс токенов находит поля без отдельной позиции AST, например имя функции,
и границы аргументов без разбиения строковых литералов и вложенных выражений.
Изменения проверяются до единственного коммита. Замена оператора сохраняет AST
операндов; изменение списка сохраняет комментарии и проверяет порядок параметров.
Сигнатуры проверяются по известным лексическим определениям без исполнения кода.
Неизвестная распаковка, декораторы и переопределённые вызываемые объекты не дают
предположительных ошибок числа аргументов. Проверка переименования охватывает
затенение, присваивания, объявления и именованные аргументы.

Код и генерируемые комментарии используют общую геометрию цветовых областей и
состояний взаимодействия. Отдельная заливка комментариев после выделения стирала
наведение и приводила к расхождению цветов. Отдельно рисуются только `#`, символ
и текст. `#` следует отступу содержащего оператора; символ может выравниваться
по вложенному выражению. Метки переноса явно устанавливают кисть и перо:
унаследованная кисть при рисовании рамки могла снова залить метку тёмным цветом.
Регрессии проверяют контраст пикселей, владельца под мышью и наведение на код
и комментарии, включая вложенные блоки.
## Проверка редактора определений

Черновики определений независимы от программ и их текстовых черновиков.
Статическая проверка принимает заполнители шаблонов, не вычисляя их.
Обновление коллекций сбрасывает кеш распознавания, включая Scratch, но сохраняет
исходник и историю отмены. Проверяются восстановление ошибочного черновика,
защита встроенных определений, обнаружение внешних изменений и отказ записи
манифеста при миграции старой коллекции. Проверочные значения не должны попадать
в сохранённые значения по умолчанию или карточки библиотеки.
Элементы управления декоратором меняют исходник с обычной текстовой отменой.
Проверки контрактов охватывают лексическое переименование, фиксированные части
блока, типы и единицы, общие функции без дублирования, очистку зависимостей,
обновление библиотек и сохранение зависимостей Scratch. Миграция сохраняет
развёрнутые алгоритмы и исторические исходники; ошибки проверки и записи
не должны оставлять коллекцию без возможности восстановления.

## Проверка учебных уровней и цвета

Повторный слой Multiply затемнял уже нарисованный блок при выделении. Одного
увеличения насыщенности оказалось недостаточно для очень светлых цветов.
Теперь насыщенность повышается, а светлота умеренно снижается до единственного
прохода окраски при неизменном тоне. Проверяются цвет и пиксели вложенных блоков:
комментарии и код меняются вместе, потомки сохраняют собственный тон.

Уровни обозначают порядок введения возможностей и накапливаются. Начальные
двадцать блоков дают последовательности с мотором, датчиком и колёсной базой
без продвинутых карточек. Проверяются развёртывание, контекстная вставка и полные
учебные примеры на трёх виртуальных профилях. Установленные на компьютере аналоги
MicroPython-модулей не должны расширять возможности прошивки, в частности
разрешать `urandom` на BOOST. Виртуальные движения базы учитывают геометрию колёс
и конечные положения при постоянной скорости моторов, но не моделируют
ускорение, проскальзывание, гироскопические поправки и различия режимов торможения.
На дуге колёса завершают движение одновременно, а не вращаются с одинаковой
угловой скоростью. Вывод хаба записывается и печатается; входы хаба задаются в тестах.
Алгоритм пульта проверяется с заданными нажатиями и виртуальными моторами;
подключение Bluetooth и калибровка Car требуют оборудования. Типы и подсказки
вложенных вызовов, например `hub.imu.heading()`, используют общий разбор пути
атрибутов от объекта до метода.
Завершение движения проверяется по неокруглённой позиции: округление показания
перед проверкой допуска могло остановить мотор за пределами этого допуска.
Команды мотора с ограничением времени используют общие часы World. Новая команда
заменяет прежний срок остановки; ожидающий вызов может завершать только своё
движение. Отмену и границу времени проверяйте явными шагами модели. Интеграционные
тесты допускают предусмотренную погрешность завершения в один градус и проверяют
нулевую скорость, а не точное напечатанное значение угла.

## Инварианты определений и примеров

Значение по умолчанию блока вычисляется в месте вставки. Поиск зависимостей
помощников должен анализировать тело декорированного блока, не принимая значения
по умолчанию за ссылки на помощников модуля. Аннотации Python задают типы, а не
исполняемые блоки значений. Ключи словаря — произвольные выражения, не обязательно
числовые индексы.

Контекстные действия используют блок под указателем. В раскрытом составном блоке
правка затрагивает указанное действие; переход по-прежнему может открыть определение
составного блока. Исторический переход сохраняет путь и версию распознанного
определения независимо от установленной текущей версии. Подсветка связанных полей
опирается на идентичность параметра и экземпляра блока, а не на совпадение текста.

Реестр должен учитывать каждый исходный файл поддерживаемых семейств хабов в
зафиксированной версии. Проверяйте восстановление исполняемого AST и компиляцию
MicroPython отдельно от последовательности виртуальных команд. Исключайте общие
плейсхолдеры присваивания и вызова при проверке покрытия операций устройств.
Явно отмечайте заданные сценарием входы и поведение, требующее аппаратуры.
Успешная компиляция не заменяет испытания физического робота.

## Личные библиотеки, версии и контуры

Личная коллекция подключается неявно и одинаково во всех интерфейсах. Определение
пути не создаёт каталогов; тесты изолируют его через общий модуль путей.
В рабочее пространство записываются только явные подключения коллекций проекта.
Встроенные коллекции поставляются с приложением.

До изменения опубликованных определений выполните `little-tinker-rig next-block-version
КАТАЛОГ MAJOR.MINOR.PATCH` или соответствующее действие редактора. Снимок включает
текущие модули и манифест, без рекурсивного копирования предыдущей истории.
До регистрации проверяются временная коллекция и неизменность исходников.
При ошибке записи манифеста новый снимок удаляется; незарегистрированная история
не считается действующими модулями. Отпечатки реализаций уже разделяют помощники:
проверяется исполнение двух версий в одной программе и Undo явного обновления.
Закрепление точной версии сохраняет прежнюю строгую семантику.

Контуры используют владельцев логических блоков и общую геометрию заливки
исходника и комментариев. Непрозрачные однопиксельные линии разделяют общие границы
без изменения раскладки. Проверяются одноцветные соседи, вложенные комментарии,
прокрутка, оформление ошибок и неизменность координат вставки. Работа ограничена
видимой областью; внешний вид проверяется при разных масштабах DPI.

## Сквозная проверка занятий

Проверяйте путь через видимые элементы управления от пустого документа до
сохранения и исполнения на виртуальном хабе. Одни вызовы Session не проверяют
выбор карточек, фокус, диалоги и попадание мыши при переносе. Всё окно должно
помещаться на тестовом экране; перед щелчком нужна завершённая раскладка.
При скрытых строках и разной высоте карточек построчная прокрутка могла оставлять
нужный блок за пределами окна. Используйте пиксельную прокрутку и проверяйте
видимость выбранной карточки.

Пустое тело с `pass` прежде всего служит местом вставки. Проверяйте его до
расширения выбора на весь распознанный блок. Проверки охватывают тела циклов,
ветвей и функций, добавление кнопкой и перетаскивание.

Вызовы пользовательских функций разделяются на действия и выражения со значением.
Возвраты и `yield` учитываются только в собственном теле функции, без вложенных
определений. Аннотация результата учитывается, результат декоратора неизвестен.
Проверяйте два последовательных вызова после изменения аргумента и вставку
функции со значением в выражение.

Признак документа без выбранного имени хранится в его странице и точке
восстановления. Save, Run, Upload и сохранение при закрытии используют одну
отменяемую операцию выбора имени. Запуск редактора не создаёт файл. Сохранение
явно указанного пути и проверка внешних изменений продолжают работать.
При отмене не запускается обмен с хабом; выбор имени сохраняет текст и Undo.

Проверяйте переведённый интерфейс с открытой консолью на экране ноутбука.
Навигация по режимам — узкая панель постоянной ширины с иконками и локализованными
подсказками. Имена остаются в модели элементов для средств доступности, но подписи
не рисуются. Иконки выровнены по центру; смена языка или шрифта не расширяет панель.
Низкая панель прокручивается без выбора другого режима.
Скрытые режимы урока отключены, Home/End выбирают видимые строки: одного скрытия
строки QListWidget недостаточно для исключения из навигации с клавиатуры.
Проверяйте прокрутку, выбор, скрытые режимы, перевод подсказок и отрисовку иконок.
Начальный размер окна учитывает доступную область экрана.

## Инварианты уроков и просмотрщика

Запрошенный шаг сборки сохраняется до получения реального числа шагов из модели.
Неполные описания шагов и ошибки загрузки не должны обрезать сохранённый прогресс.
Навигация включается после загрузки; только тогда ограничивается слишком большой
сохранённый номер шага.

Стартовую программу применяйте через `commit` редактора: прямой Document commit
оставляет выделение в старом синтаксическом дереве. Переходы этапов не меняют код.
Перед заменой архива сохраняйте черновики и Scratch; при ошибке записи архива
проект должен остаться изменённым. Восстановление сохраняет исходный хеш архива
для обнаружения внешних изменений.
Рабочую папку закрытого проекта удаляйте только после успешного обновления
точки восстановления: при ошибке записи старая точка всё ещё ссылается на неё.

Палитра урока и каталог распознавания независимы. Скрытый на текущем этапе блок
должен оставаться редактируемым, а поиск, подсказки выражений и перетаскивание —
учитывать палитру.

Для OpenGL проверяйте настоящий QOpenGLWidget в Wayland и X11 наряду с шейдерами
без окна: проверка только X11 не обнаруживает ошибки подключения к EGL.
Получайте функции OpenGL через `QOpenGLContext.getProcAddress`: Qt владеет
нативным контекстом и выбирает его реализацию. Не выбирайте GLX по признаку Linux,
не создавайте второй нативный контекст и не используйте кеш ModernGL другого
виджета. На каждой отрисовке получайте текущий framebuffer Qt, не используйте
нулевой. Короткая проверка контекстов запускается с `QT_QPA_PLATFORM=wayland`
или `xcb`; на тестовой платформе Qt offscreen без GL она пропускается.
Загружайте геометрию вне потока GUI. Камера и шаги используют уже загруженные
сетки и буферы экземпляров деталей.
Обход модели должен сохранять непосредственную геометрию рядом со ссылками
на детали, включая её шаг сборки; проверяйте такие смешанные модели.

Сторонние библиотеки деталей — внешние ресурсы, а не исходные материалы урока.
В Git хранятся ссылки с фиксированной версией, в общем пользовательском кеше —
проверенные архивы. Скачивание, чтение ZIP и подготовка геометрии выполняются вне
потока GUI; индекс ZIP создаётся один раз, читаются только необходимые записи.
Не копируйте скачанные детали в каталоги уроков для включения в пакет.
Офлайн-экспорт работает со снимком и создаёт отдельный архив с черновиками,
Scratch, всеми зависимостями деталей и лицензиями, не отмечая исходный проект
сохранённым. Проверяйте отмену и ошибку контрольной суммы на синтетических архивах,
а экспортированный проект открывайте после удаления кеша и отключения сети.
Проверка соединений учебной модели необязательна: укажите проверенный локальный
`complete.zip` в `LITTLE_TINKER_RIG_TEST_LDRAW`. Обычные тесты не скачивают библиотеку.

Включайте в пакет только созданные для урока Python, JSON, Markdown, текстовые
уведомления, модели LDraw (`.ldr`/`.mpd`) и иллюстрации PNG/SVG. Фильтры уроков
в `MANIFEST.in` и `build_support.py` должны совпадать: оба исключают каталог
`ldraw`, архивы и рабочее состояние. Правила Git ignore не управляют упаковкой
Python. Проверяйте sdist и wheel с посторонними ресурсами во временной копии
исходников, включая прямую сборку wheel. Локальные рабочие заметки `AI/` исключены
из Git и дистрибутивов; актуальные решения хранятся в спецификации или документации
разработчика. Собственные материалы уроков используют MIT проекта; внешние детали
сохраняют свои лицензионные уведомления.
