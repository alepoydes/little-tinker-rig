# Подключение по USB

Для хаба с совместимой прошивкой Pybricks выберите **USB** в окне подключения.
Оставьте поле порта пустым для автоматического поиска либо укажите последовательный
порт из вашей операционной системы. Установка прошивки и передача программы используют
разные соединения: успешная прошивка не означает наличия прав на последовательный порт.

LittleTinker Rig использует публичные адаптеры закреплённой версии форка pybricksdev
для BLE, прежнего USB и USB Serial. [Установка через uv](INSTALL.md) из репозитория
устанавливает проверенные клиент и компилятор вместе.
Inventor/Prime и EV3 на совместимой новой прошивке используют
один последовательный протокол. Поддержка EV3 экспериментальная, физическая проверка
не выполнена. Прежнее окружение EV3 на Linux/SD-карте этот адаптер не обслуживает.

## Linux: нет доступа к последовательному порту

Приложение показывает фактический порт, его группу и права, затем пояснение и,
когда это уместно, команду для вашей учётной записи. **Копировать ошибку** копирует
сообщение вместе с командой. **Помощь с подключением USB** открывает эту страницу
без интернета. Такое же объяснение появляется в терминальном интерфейсе и CLI.

Например, проверьте подключённый порт и группы текущего сеанса:

```sh
ls -l /dev/ttyACM0
id
id "$USER"
```

Замените `/dev/ttyACM0` на указанный в ошибке порт. Если владельцем и группой являются
`root:dialout`, а права — `crw-rw----`, участники группы `dialout` могут читать и
записывать порт. На некоторых системах группа называется `uucp`; ориентируйтесь
на фактическую группу устройства. Для добавления своей учётной записи в `dialout`:

```sh
sudo usermod -aG dialout -- "$USER"
```

Это даёт доступ к последовательным портам данной группы. Приложение предлагает
членство только в группах последовательных портов `dialout` и `uucp`; необычный
владелец или отсутствие у группы прав чтения/записи требуют проверки администратора.

**Полностью выйдите из рабочего сеанса и войдите снова.** Запустите LittleTinker Rig,
IDE и терминал, из которых запускаете приложение, в новом сеансе. Переподключение
кабеля или перезапуск приложения из старой IDE не обновляет унаследованный список
групп. Если `id "$USER"` уже показывает группу, а `id` ещё нет, членство настроено —
осталось начать новый сеанс.

Если процесс уже входит в нужную группу, но открытие порта не удаётся, администратор
должен проверить ACL устройства (`getfacl /dev/ttyACM0`) и системные ограничения
доступа. Приложение само не меняет права или членство в группах.

## Linux: доступ для USB и установщика прошивок Pybricks

Используйте правила установленного `pybricksdev`, следуя
[официальной инструкции](https://github.com/pybricks/pybricksdev#linux-usb).
Из каталога исходников LittleTinker Rig:

```sh
uv run --extra pybricks pybricksdev udev | sudo tee /etc/udev/rules.d/99-pybricksdev.rules
sudo udevadm control --reload-rules
```

После установки правил отключите и подключите кабель хаба. Если правила уже
установлены, одна лишь ошибка последовательного порта не требует их переустановки:
правила `pybricksdev 2.3.2` относятся к USB и HID, но не к `tty`. Для `/dev/ttyACM*`
используйте настройку доступа к последовательному порту выше. LittleTinker Rig
не содержит отдельной копии этих правил устройств.

## Другие ошибки подключения

- **Порт занят:** отключитесь от хаба в Pybricks Code, других экземплярах редактора
  и последовательных терминалах, затем повторите попытку.
- **Порт отсутствует:** переподключите хаб кабелем USB с передачей данных. Имя порта
  могло измениться; выберите новое имя или автоматический поиск.
- **Нет ответа / неподдерживаемый протокол:** проверьте совместимость прошивки
  Pybricks и обычный режим работы хаба. Он не должен находиться в режиме обновления
  прошивки. Совместимость прошивки и права на устройство проверяются отдельно.
- **Windows:** последовательный хаб отображается как COM-порт, например `COM3`.
  Команды групп Linux и udev здесь неприменимы. Проверьте диспетчер устройств и
  закройте приложения, удерживающие порт.
- **macOS:** используйте обнаруженный порт `/dev/cu.usbmodem…`. Команды групп Linux
  и udev неприменимы. Закройте другие приложения и проверьте права на устройство.

Во время подключения кнопка хаба или F7 отменяет попытку; после подключения —
отключает хаб. Полный текст находится в **Консоли**: исходная системная ошибка
сохраняется вместе с пояснением следующего шага.

## Проверка подключения на Inventor

После настройки доступа подключите Inventor с совместимой прошивкой Pybricks.
Откройте **Файл → Примеры → inventor_51515_hub_check.py**
([исходник](../../examples/inventor_51515_hub_check.py)). Программа использует только
встроенные матрицу и динамик: цифры 1–3 с повышающимися тонами, затем сердце и
завершающий сигнал. Она заканчивается примерно через пять секунд, выводя этапы
и `Hub check complete.` в консоль. Моторы и датчики не нужны. Этот же пример
работает на SPIKE Prime; см. [API хаба](https://docs.pybricks.com/en/latest/hubs/primehub.html).

**Отправить на хаб** должно завершиться без запуска. **Запустить загруженную программу**
должно показать последовательность и вывести сообщения в консоль без повторной передачи. Также проверьте запуск
с загрузкой, ввод в консоль программой, которая его читает, остановку, отключение,
повторное подключение и отмену поиска отсутствующего хаба. Загрузка заменяет
программу, сохранённую на хабе.

Проверка Inventor не является аппаратной проверкой EV3. Для EV3 пока проверяются
соответствие протоколу и обмен с искусственным последовательным устройством.
