# Устройство проекта

Программа хранится обычным текстом Python. Из него строятся AST, диапазоны,
распознанные сниппеты, лексические имена и области отображения. Эти производные
данные живут только до следующего изменения исходника.

```text
Qt / Textual / CLI
        ↓
Session: сниппеты, зависимости, Scratch, файлы
        ↓
Editor: выделение, история, навигация переноса
        ↓
edit: преобразование текста → Document: проверка и фиксация
                                    ↓
                         Syntax → анализ и отображение
```

`Document` публикует новое состояние только после форматирования и компиляции.
Компиляция проверяет контекст (`break` внутри цикла, `return` внутри функции),
но не запускает программу. История хранит снимки основного текста и Scratch.
Локальный редактор может содержать ошибочный черновик; неудачное применение
сохраняет прежний документ.

Декораторы, сигнатуры, аннотации объявлений и docstring составляют единое
определение блока. Загрузка разбирает его статически, без выполнения Python.
Редактор определений, библиотека, справка и проверка полей используют эту модель.
Контракты сохраняют тип и единицу измерения; неизвестные значения допускаются,
а известные несовместимости получают диагностику. При фиксации документа
зависимости общих функций и импорты обновляются вместе с исходником и Scratch,
поэтому отмена восстанавливает их одним действием.

## Принятые решения

| Вопрос | Решение и причина |
| --- | --- |
| Форматирование | Ruff через публичный CLI, с конфигурацией внутри пакета; настройки рабочего каталога не меняют результат |
| Терминальный интерфейс | Textual: готовые редактор текста, формы, клавиатурные события и средство проверки без терминала |
| Настольный интерфейс | PySide6: текст остаётся текстом; области рисуются поверх стандартного текстового виджета |
| Библиотеки | Python-модули с декораторами блоков и общими функциями; `collection.toml` хранит сведения о коллекции и её версиях |
| История шаблонов | Подкаталоги версий, перечисленные в manifest; распознавание по AST без меток отдельных блоков |
| Workspace | Необязательный соседний `.py.ltr.json`: Scratch, пути коллекций, закреплённые версии; AST туда не записывается |
| Комментарии | Соседние ведущие и конечные комментарии принадлежат инструкции; заголовок остаётся с файлом |
| Типы и единицы | Строковые аннотации параметров, результатов и создаваемых переменных; проверка известных контрактов без преобразования чисел |
| Связь с роботом | Тонкая оболочка публичных API pybricksdev; ядро редактора не зависит от транспорта |
| Управление | Общий `ControlState`, текстовые кадры stdin, небольшой обычный Python-модуль на хабе |
| Ручной режим | Общие `MotorBinding` и `HubInfo`; монитор управляет моторами и отдаёт телеметрию; пользовательская программа запускается отдельно |
| Виртуальный хаб | Отдельный прерываемый процесс, детерминированная модель устройств и явное подмножество публичного Pybricks API |
| Помощь | Единственный источник Markdown — `doc/`; сборка копирует его в пакет для автономной работы |
| Геймпад | Необязательный pygame-ce / SDL, тот же формат состояния, что у экранного джойстика |
| Оформление | Семантические роли и палитра в ядре; геометрия, анимация и интенсивность в интерфейсе |
| Документы Qt | Отдельная `Session` и текстовый черновик на вкладку; команды окна обращаются к активной вкладке |
| Параметры | Диапазоны выражений выводятся из AST и шаблонов; раскрывающиеся поля не добавляют разметку в исходник |
| Языки | gettext PO/MO, динамическая смена подписей без пересоздания редакторов; Babel только при разработке |

Порядок выбора пересекающихся шаблонов и правила обновления описаны в
[руководстве автора коллекции](snippets.md). Контракты диапазонов и операций —
в [API](api.md).

## Границы ответственности

Структурная допустимость переноса не означает сохранения смысла программы.
Редактор разрешит перенести присваивание после использования переменной;
лёгкая диагностика может предупредить о проблеме, но не доказывает алгоритм.
Анализ имён лексический, без полного вывода типов, единиц и ветвей выполнения.

AST не сохраняет комментарии. Поэтому перенос и локальное редактирование
работают со срезами исходного текста; генерация через `ast.unparse` применяется
к разворачиваемому шаблону. При обновлении алгоритма комментарии переносятся
перед новым телом: прежняя внутренняя привязка может потерять смысл.

Сохранение исходника и workspace не является общей файловой транзакцией.
Каждый файл заменяется атомарно, а перед записью исходника сохраняется
объединение прежнего и нового Scratch. Прерывание может оставить дубликат,
но не должно удалить единственную сохранённую копию фрагмента. Внешние изменения
обоих файлов обнаруживаются перед сохранением; совместное редактирование с
блокировками файлов не реализовано.

Тесты интерфейсов проверяют перевод жестов в операции общего ядра и управление
виртуальным хабом через рабочий asyncio-поток. Модель движения имеет явное время
и не моделирует инерцию, нагрузку или физику робота. Служебный монитор запускается
на моделях всех целевых хабов, включая BOOST без универсального `PUPDevice`.
Проверки реальных Bluetooth, USB и характеристик моторов выполняются отдельно.

Полный текстовый редактор держит незавершённый Python отдельно от `Document`.
Сохранение, запуск и переход к структурному виду фиксируют его общей операцией
ядра. Qt сохраняет отмену текстовых правок и форматирования. Робот и виджеты
обмениваются сигналами; жизненный цикл соединения сериализован, а команды
контроллера не создают очередь устаревших значений.
