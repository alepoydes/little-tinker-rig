# Создание библиотек блоков

В [редакторе блоков](block-editor.md) можно изучать встроенные определения,
редактировать пользовательские и видеть предпросмотр над исходником. Определения
разбираются статически: редактор не исполняет декораторы, значения по умолчанию,
импорты или тела функций.

## Коллекции и группы

Коллекция содержит Python-модули и файл `collection.toml`:

```toml
[collection]
id = "my_robot"
version = "1.0.0"
format = 2
```

В манифесте находятся сведения о коллекции и необязательные записи `[[history]]`
с полями `version` и `path`. Модуль задаёт группу справки, его docstring — название и
описание группы, функция с декоратором — блок. Идентификатор блока имеет вид
`collection/module/function`. Обычные функции без декораторов служат помощниками
и не появляются в панели блоков. Без метаданных каталога модуль также задаёт
собственную ветку. Например, `__category__ = "movement"` помещает его карточки
в категорию «Моторы и движение»; декоратор может переопределить её через `category`.
Близкие формы могут ссылаться на основную карточку через `family` и задавать
переводимое название варианта через `variant`. Каждая форма остаётся отдельным
обычным определением Python.

Подключение: `little-tinker-rig --collection ./my_robot qt main.py`. Каталоги исторических
версий должны находиться внутри коллекции. Старые определения продолжают
распознаваться; явное обновление сохраняет совместимые параметры и имена.
Переход между основными версиями требует ручной проверки.

## Начало новой версии коллекции

Перед изменением опубликованных определений сохраните предыдущую версию через
**Начать следующую версию…** в редакторе блоков или командой:

```sh
uv run little-tinker-rig next-block-version ./my_blocks 1.1.0
```

Та же команда используется для встроенных коллекций в `little_tinker_rig/snippets/` при
подготовке выпуска. Номер имеет вид `MAJOR.MINOR.PATCH`. Команда проверяет временную
копию коллекции, архивирует текущие Python-модули и `snapshot.toml` в
`history/<предыдущая-версия>/`, затем обновляет `collection.toml`. Существующие архивы
не перезаписываются. Черновики предварительно нужно сохранить или отбросить.
Исторические определения входят в wheel и исходный дистрибутив. Каталог истории
без записи в манифесте никогда не загружается как действующий модуль.

Явное обновление сохраняет подстановки, открытые имена и комментарии. Изменения
типов/единиц параметров, контракта результата или объявлений, а также основной
версии требуют ручного редактирования. За смысловую совместимость отвечает автор:
совпадение сигнатур само по себе не доказывает равенства поведения. Функции сохраняют
исходные имена и одну реализацию в программе. Явное обновление функции меняет общее
определение для всех вызовов; изменение сигнатуры вызова требует ручного
редактирования. Одна лишь перезагрузка библиотеки сохранённый код не обновляет.

## Два способа вставки

```python
"""Motors

Connect motors and control their movement.
"""

@inline_block(level="beginner", icon="⚙", color="state", names=("motor",))
def create_motor(port: "Port" = Port.A):
    """Connect a motor to a hub port."""
    from pybricks.parameters import Port
    from pybricks.pupdevices import Motor

    motor: "Motor" = Motor(port)

@block(level="intermediate", icon="↻", color="action")
def move_for(motor: "Motor" = motor,
             speed: "number[deg/s]" = 300,
             duration: "int[ms]" = 500):
    """Run a motor for a time and brake it."""
    from pybricks.tools import wait

    motor.run(speed)
    wait(duration)
    motor.brake()
```

`@inline_block` вставляет тело функции. Единственный `return expression` задаёт
блок-выражение. Созданные переменные находятся в области вставки; автоматическое
переименование предотвращает конфликты и захват чужих имён. Повторное вхождение
параметра повторяет переданное выражение вместе с его побочными эффектами.

`@block` вставляет вызов обычной автоматически добавляемой функции. Аргументы
вычисляются один раз при вызове, локальные переменные остаются внутри функции.
Функция с результатом задаёт блок-выражение, действие — блок-инструкцию. Режим
выбирается явно: редактор не заменяет инлайн-код вызовом функции автоматически.

Декораторы нужны только определениям библиотеки. Программа для хаба содержит
обычный Python, импорты и вспомогательные функции; среда LittleTinker Rig на хабе не нужна.

## Свойства в исходнике

| Свойство | Значение |
|---|---|
| `level` | Уровень введения: `beginner`, `intermediate`, `advanced`, `expert`; по умолчанию `intermediate` |
| `icon` | Непустой символ или короткий текст; по умолчанию `▶` |
| `color` | Роль палитры или `#RRGGBB`; по умолчанию `snippet` |
| `names` | Переименуемые объявления инлайн-блока; по умолчанию пусто |
| `kind` | Необязательное явное значение `statement` или `expression` |
| `context` | Обёртка `loop` или `async` для инструкций, требующих соответствующего контекста |
| `category` | Ветка каталога; наследует `__category__` модуля, иначе использует заголовок модуля |
| `family` | Полный идентификатор основного блока, например `my_blocks/motors/turn`; пусто для отдельной основной карточки |
| `variant` | Переводимое название формы; участник семейства без названия — алиас для распознавания и прежних лабораторных |
| `advanced` | Кортеж имён необязательных параметров для раздела дополнительных настроек |
| `bindings` | Словарь имён параметров и общих ключей полей семейства; остальные параметры сохраняют свои имена как ключи |

Роли палитры: `control`, `loop`, `action`, `value`, `state`, `definition`,
`placeholder`, `snippet`, `warning`. Значения свойств должны быть литералами.
`all` — накопительный фильтр панели, а не уровень блока. Одно определение задаёт
оформление карточки, вставленного блока, предпросмотра и страницы справки.

Сигнатура задаёт поля выражений и значения по умолчанию. Запись `motor=motor`
обозначает выражение в месте вставки, а не объект, создаваемый при загрузке
библиотеки. Значения по умолчанию позволяют вставлять блок без диалога.
Docstring служит справкой и поисковым текстом. Описания пишутся на английском;
переводы описаний блоков и групп подключаются через gettext.

Формы семейства должны иметь совместимые вид (инструкция или выражение) и
требования к контексту, а также ссылаться прямо на основной блок той же коллекции;
цепочки ссылок запрещены. У каждой формы остаются свои сигнатура, уровень, тело
и идентификатор. Смена категории или перевода не меняет программы и личные ссылки.
Значения между совместимыми общими полями переносятся только при явном изменении
варианта. Пропуск аргумента отличается от передачи `None` или вычисления значения
по умолчанию. Эти свойства можно менять через [редактор блоков](block-editor.md)
с предпросмотром и обычной текстовой отменой.

## Типы и единицы

Аннотация — строка с типом и необязательной единицей числовой величины:

| Аннотация | Требование |
|---|---|
| `"Motor"` | Объект мотора |
| `"int"` | Целое число, кроме логического значения |
| `"number[deg/s]"` | Числовая угловая скорость |
| `"int[ms]"` | Целая длительность в миллисекундах |
| `"Motor | DriveBase"` | Один из двух типов объектов |

Числовые типы: `int`, `float`, `number`. Единицы: `deg`, `deg/s`, `deg/s²`, `mm`,
`mm/s`, `ms`, `s`, `%`, `N`, `Hz`. На хабе остаются обычные числа; автоматического
пересчёта единиц нет.

Входы аннотируются в сигнатуре. Запись вроде `-> "number[mm]"` описывает именно
возвращаемое значение. Действие может не иметь такой аннотации или использовать
`-> "None"`. Тип создаваемой переменной задаётся в теле, например `motor: "Motor"`.
Существующие присваивания без аннотаций тоже распознаются как этот блок.

Проверка различает совместимость, несовместимость и недостаток сведений. Заведомо
неверный тип или единица вызывают красную диагностику; динамическое значение
неизвестного типа само по себе не считается ошибкой. Числовой литерал принимает
единицу поля. Подсказки, перетаскивание и диагностика используют общий контракт.
Это ограниченный статический анализ, а не полная система типов Python или
алгебра физических размерностей.

## Открытые поля и имена

В распознанном блоке редактируются параметры сигнатуры и явно открытые объявления.
`names=("motor",)` разрешает переименовать созданную переменную вместе со связанными
обращениями в окружающем коде. Для вложенных объявлений используются пути:
`names=("action", "action.value")` открывает имя функции и её параметра.
В `names` можно также указать параметр сигнатуры, используемый как имя создаваемой
переменной. Проверяются конфликты областей видимости и захват чужих обращений.

Методы, операторы, константы и внутренние имена фиксированы, если не находятся
внутри открытого выражения. Списки в открытых выражениях можно менять структурно.
Для изменения устройства раскройте блок или отредактируйте Python. Потерявший
соответствие определению код становится обычным Python без прежнего описания.

## Зависимости и помощники

Импорты допускаются на уровне модуля и внутри инлайн-шаблона. Необходимые глобальные
импорты собираются в управляемой секции; пользовательские импорты сохраняются.
Импорты внутри генерируемых функций остаются локальными по обычным правилам Python.

Функции без декораторов в том же модуле могут быть общими для нескольких блоков.
Редактор добавляет их зависимости один раз в управляемую секцию после импортов,
сохраняя исходные имена функций. Разные определения с одинаковым именем требуют
явного переименования; незаметной подмены реализации не происходит.
После удаления последнего использования лишние функции и импорты удаляются.
Учитываются обращения из обычного кода и Scratch, в том числе незавершённого.
Отмена восстанавливает код и зависимости вместе. При обновлении библиотеки уже
сохранённые реализации остаются в программе; применение определений не переписывает
открытые документы.

Модуль библиотеки содержит docstring, импорты и определения функций. Сигнатура
блока имеет фиксированные параметры; инлайн-шаблоны не поддерживают рекурсивные
вызовы шаблона, непустые классы и объявления `global`/`nonlocal`. Разрешён отдельный
пустой каркас класса: опубликованное имя можно переименовать, а тело заполнить
обычными блоками Python. Обычные помощники сохраняют
обычные сигнатуры Python и локальные области видимости.
При вызове декорированного блока из вспомогательного кода все его поля передаются
явно: значения по умолчанию заполняют поля вставляемого блока, а не сигнатуру
исполняемой функции. Для обычных аргументов Python по умолчанию используйте
вспомогательную функцию без декоратора.

## Управляющие инструкции

Чтобы сохранить `return` как инструкцию, используйте `kind="statement"`:

```python
@inline_block(kind="statement", level="intermediate", icon="↩", color="control")
def return_value(value=0):
    """Return a result."""
    return value
```

Для `await` задайте `context="async"` и единственную обёртку `async def`.
Вставляется только её тело; Python запрещает вставку вне асинхронной функции.
Встроенная группа **Совместные задачи** содержит определение задачи, ожидание
и запуск основной задачи.

Для `break` и `continue` задайте `context="loop"` и единственную обёртку `while`.
Вставляется только её тело. Обёртка делает определение корректным Python;
место вставки всё равно проверяется на принадлежность циклу. Контекст и способ
вставки не кодируются в типе результата.

## Переход со старого формата

Старые шаблоны без декораторов и таблица `[levels]` продолжают читаться. Перевод
коллекции в новый формат:

```sh
little-tinker-rig migrate-blocks ./my_robot
little-tinker-rig migrate-blocks ./my_robot --write
```

Первая команда показывает изменения, вторая применяет проверенное преобразование.
Инлайн-алгоритмы, уровни и исторические версии сохраняются; программы не меняются.
Редактор блоков также преобразует открытый старый модуль в текстовый черновик
и удаляет устаревшие записи уровней при его сохранении.
