# Разработка

Проект использует uv, Python 3.11+ и обычную структуру Python-пакета.
Рабочая версия интерпретатора указана в `.python-version`; точные зависимости —
в `uv.lock`. В окружении разработки устанавливаются все интерфейсы:

```sh
uv sync --all-extras --locked
uv run --all-extras pytest
uv run ruff check .
uv run black --check .
uv build
```

`uv run` синхронизирует окружение с выбранными extras. Для запуска интерфейса
указывайте его явно: `uv run --extra qt pyblocks-qt`.

Ядро зависит только от стандартной библиотеки и Black. Black запускается через
публичный CLI; конфигурация берётся из пакета, а не из текущего каталога.
Форматирование выполняется только на границе зафиксированной операции.

## Инварианты

- Текст программы — единственное сохраняемое представление программы.
- AST, диапазоны, области отображения и распознавание можно построить заново.
- Зафиксированный документ проходит `ast.parse` и `compile` без исполнения.
- Синтаксическая ошибка, ошибка форматирования или переноса не меняет документ
  и историю. Основной текст и Scratch входят в одну транзакцию.
- Диапазоны ядра используют индексы Unicode-символов, полуинтервал `[start, end)`.
  UTF-8-координаты AST преобразуются на входе. Строки нумеруются с 1, столбцы с 0.
- Узлы AST и позиции вставки принадлежат одной ревизии исходника.
- Тесты проверяют результат и инварианты, а не внутреннее устройство функций.
- Преобразование исходника проверяется отдельно на сохранение комментариев,
  строковых значений (включая многострочные f-строки) и лексических привязок.
  Синтаксическая валидность сама по себе не доказывает сохранность этих данных.
- Сохранение нескольких файлов проверяется с отказом между отдельными записями,
  причём для переноса фрагмента в обоих направлениях.
- Внешние изменения проверяются для исходника и Scratch; контрольная сумма
  соответствует прочитанным или записанным байтам, а не последующему чтению файла.
- Обновление отображения не должно менять логическое выделение. События
  программного обновления виджетов отделяются от пользовательского выбора.
- Исторический шаблон проверяется вместе с реальной встроенной библиотекой:
  общие шаблоны одиночных инструкций не должны скрывать узнаваемый алгоритм.
- Ошибочный текстовый черновик не заменяет зафиксированный документ или файл;
  форматирование остаётся отменяемой текстовой операцией.
- Поддержка устройства проверяется по доступным API каждой модели. Компиляция
  общего helper не доказывает наличия модулей на BOOST, Inventor или Technic.
- Проверки контроллера наблюдают движение, остановку и показания устройств,
  включая истечение команды и отключение. Отмена загрузки завершается перед
  следующей операцией жизненного цикла, чтобы не оставить процесс или соединение.
- Потоки Qt/asyncio проверяются вместе: имитация одного транспорта не проверяет
  доставку сигналов и своевременную остановку. Для таких тестов среда должна
  разрешать локальный `socketpair`, используемый самим asyncio.

## Проверки без оборудования

`test_virtual.py` проверяет модели Inventor/Prime, BOOST и Technic, выполнение
обычной программы, датчики, тайм-аут моторов, остановку бесконечного цикла и
настоящий код `hub_monitor.py` поверх моделируемого API устройств.
`test_frontends.py` проверяет эти подключения через Qt, движения стиков,
назначения вращения/серво, отключение и зеркалирование физического контроллера.
Qt работает с `QT_QPA_PLATFORM=offscreen`; оборудование и радиосвязь не нужны.

Компиляция служебных программ для MicroPython (extra `pybricks`):

```sh
uv run --extra pybricks python -m mpy_cross_v6 pyblocks/pybricks/hub_monitor.py -o /tmp/pyblocks-monitor.mpy
uv run --extra pybricks python -m mpy_cross_v6 pyblocks/pybricks/hub_controller.py -o /tmp/pyblocks-controller.mpy
```

Wheel проверяется из каталога вне репозитория: справка и настройки форматтера
должны браться из установленного пакета. При изменении документации сборка
включает актуальный `doc/` без второй поддерживаемой копии.

## Стоимость операций

Индекс строится линейным обходом AST. Форматирование и повторный разбор выполняются
при фиксации; наведение и навигация используют готовый индекс. История хранит
снимки текста и Scratch, что подходит для учебных программ небольшого размера.

Перечисление мест переноса проверяет компиляцией один кандидат на список
инструкций: внутри списка контекст компилятора одинаков. Если в документе есть
зависящие от порядка объявления `global`, `nonlocal` или `__future__`, проверяется
каждая позиция. Перед фиксацией готовая программа всегда компилируется заново.
Стоимость обычного случая — O(число списков × размер программы + число позиций).
Для зависимых от порядка объявлений сохраняется точный, но более дорогой путь
O(число позиций × размер программы). Оптимизированный набор целей сравнивается
в тестах с независимым перебором и компиляцией каждого преобразования.

Отказ одного устройства при групповой команде проверяется после успешного
запуска предыдущего мотора: обработчик ошибки должен тормозить и уже начавшие
движение устройства, а не только моторы из предыдущего кадра управления.

## Документы и прямое редактирование

Вкладки документов сохраняют независимые черновики и историю. Команды окна
действуют на активный файл. Перевод не меняет пользовательский текст.
Предварительный вид вставки использует ту же подстановку параметров и защиту
имён, что фиксация. Цели учитывают положение `global`, `nonlocal` и `__future__`.
Редактирование параметра сохраняет приоритет операций и меняет все вхождения
одного параметра шаблона. Поле старой ревизии не может изменить новый документ.

Вставка из библиотеки проверяет каждую позицию отдельно один раз при начале
перетаскивания. Дальнейшее движение указателя выбирает из готовых целей.
Поля параметров и их геометрия пересчитываются при смене ревизии или раскрытии
сниппета; наведение не запускает форматирование.

`test_ux.py` проверяет несколько файлов, сохранность ошибочных черновиков,
совпадение предварительного и вставленного кода, раскрывающиеся поля, пульсацию
фона и перевод интерфейса и справки. `examples/courier.py` проверяется как настоящая
программа виртуального хаба: калибровка, препятствие, доставка, завершение маршрута,
аварийная остановка, истечение времени и отключение датчика. После выхода все
доступные моторы должны тормозиться.

```sh
uv run --extra pybricks python -m mpy_cross_v6 examples/courier.py -o /tmp/pyblocks-courier.mpy
```

## Переводы

Исходный язык подписей Qt — русский. gettext-каталоги находятся в
`pyblocks/locale/<код>/LC_MESSAGES/pyblocks.po`, скомпилированные `.mo` входят
в пакет. `locale/languages.json` задаёт коды языков и их собственные названия
для меню. Babel нужен только разработчику; приложение использует стандартный gettext.

```sh
uv run python tools/translations.py update
# Заполнить новые msgstr в .po и проверить перевод.
uv run python tools/translations.py compile
uv run python tools/translations.py check
```

`update` извлекает статические подписи Qt, вызовы `tr` и docstring сниппетов,
добавляет ссылки на исходники и сохраняет уже готовые переводы. `check` находит
пропуски, неподтверждённые переводы, несовпадающие поля форматирования и устаревший
бинарный каталог. `.po` и `.mo` сохраняются вместе в репозитории.

Статические подписи виджетов переводит `qt.localization.localize`. Динамический
текст создаётся через `tr("Сообщение {name}", name=value)`; подстановка выполняется
после поиска перевода. Пользовательский текст, значения параметров и консольный
вывод не являются сообщениями интерфейса. При добавлении языка создайте раздел
`doc/<код>/`, сохранив относительные пути страниц: так текущая страница справки
сохраняется при переключении языка. Общие изображения находятся в `doc/images/`.
